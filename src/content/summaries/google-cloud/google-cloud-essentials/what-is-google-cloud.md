Google Cloud lets developers run code, store data, and analyze it on Google's computers rather than operating all the physical infrastructure themselves. Ryan introduces the main service categories, then combines them in a fictional social app. [00:00–01:03](https://www.youtube.com/watch?v=kzKFuHk8ovk&t=0s), [04:11–05:16](https://www.youtube.com/watch?v=kzKFuHk8ovk&t=251s)

### Key Points Covered

- Managed services take on operational work as well as hosting. Ryan uses a retailer's seasonal demand to illustrate the burden of buying extra hardware and managing database capacity and backups, then presents a managed database as an alternative. [01:03–02:05](https://www.youtube.com/watch?v=kzKFuHk8ovk&t=63s)
- Hosting choices range from virtual machines in Compute Engine to managed containers in Cloud Run and web applications in App Engine. For data, Cloud Storage holds files, Cloud SQL runs familiar relational databases, and Firestore keeps document records synchronized with clients in real time. [02:05–03:08](https://www.youtube.com/watch?v=kzKFuHk8ovk&t=125s)
- Prebuilt AI APIs let an app use capabilities such as finding objects in images or analyzing text without training a model. Vertex AI is presented for developers who want to train, host, and manage their own models. [03:08–04:11](https://www.youtube.com/watch?v=kzKFuHk8ovk&t=188s)
- The fictional social app stores photos in Cloud Storage, profile records in Firestore, uses Vision AI to identify objects in photos, and runs on Cloud Run. The example shows why an application may combine several services rather than choose just one. [04:11–05:16](https://www.youtube.com/watch?v=kzKFuHk8ovk&t=251s)
