Repeated application failures can bury useful information in logs. Error Reporting groups occurrences by their stack traces (the recorded sequence of calls behind an error), so a team can track an error type instead of reviewing every occurrence separately. [00:00–02:06](https://www.youtube.com/watch?v=GANi9eRxhHs&t=0s)

### Key Points Covered

- Errors can reach Error Reporting through appropriately formatted application logs or direct API calls. The service groups them and can notify the team when a new error group appears. [00:00–02:06](https://www.youtube.com/watch?v=GANi9eRxhHs&t=0s)
- Because occurrences are deduplicated by stack trace, each error type appears as one entry. Its summary shows when the error first appeared, how often it has occurred, and how recently. [01:05–02:06](https://www.youtube.com/watch?v=GANi9eRxhHs&t=65s)
- Each error has a resolution status: open by default, or set to acknowledged, resolved, or muted. An error can also be linked to an issue in a bug-tracking system. [01:05–02:06](https://www.youtube.com/watch?v=GANi9eRxhHs&t=65s)
- Error Reporting shows which errors occur. The video leaves tools for understanding and fixing their causes to later episodes. [02:06](https://www.youtube.com/watch?v=GANi9eRxhHs&t=126s)
