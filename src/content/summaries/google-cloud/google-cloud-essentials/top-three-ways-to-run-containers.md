Containers package an application and its dependencies, but someone still has to run and scale them. This 2020 overview compares Google Kubernetes Engine (GKE), Cloud Run, and Compute Engine by how much of that infrastructure a team controls. [00:00–04:16](https://www.youtube.com/watch?v=jh0fPT-AWwM&t=0s)

### Key Points Covered

- **GKE coordinates containers across a cluster.** Kubernetes schedules and scales containers and tracks their health. The overview shows controls for machine types and locations, with managed features for node repair and upgrades. [00:00–02:08](https://www.youtube.com/watch?v=jh0fPT-AWwM&t=0s)
- **Cloud Run removes cluster setup.** The example deploys a stateless container by selecting a location, name, and authentication requirements. The platform manages scaling, including scaling to zero when idle. [02:08–03:12](https://www.youtube.com/watch?v=jh0fPT-AWwM&t=128s)
- **Compute Engine keeps a VM-based workflow.** Containers run on virtual machines, allowing teams to retain familiar tools. The example uses Container-Optimized OS, a smaller operating system with a preinstalled container runtime; managed instance groups can add scaling and rolling updates across VMs. [03:12–04:16](https://www.youtube.com/watch?v=jh0fPT-AWwM&t=192s)
