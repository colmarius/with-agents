Matt Dailey, CEO and founder of Ref, calls the gap between higher agent output and unchanged team impact “velocity sickness.” He argues that teams should move their hardest review earlier, keep consequential decisions with people, and use durable shared plans as the state from which agents act.

This is a founder presenting both a workflow argument and the problem his product addresses. The talk offers useful operating guidance, but it does not measure a 10x productivity gain or compare shared documents with other coordination approaches.

### Key Points Covered

- **More output can overwhelm the team around it**: Dailey connects coding-agent adoption to unmergeable pull-request volume, merge conflicts, fragmented work, and “agent bankruptcy,” where developers abandon sessions they can no longer reconstruct [00:01:00]-[00:03:35].
- **The central risk is losing decision ownership**: His strongest concern is not wasted tokens but engineers allowing agents to make consequential product and code decisions they no longer understand or own [00:02:41]-[00:04:26].
- **Impact, not generated volume, is the useful constraint**: A newsletter writer producing a book's worth of material each week illustrates his broader point: output that exceeds its audience's capacity can feel productive without creating value [00:04:26]-[00:06:29].
- **Agent work shifts the human role toward planning and polish**: Dailey contrasts implementation-centered IDE work with a workflow where people explore the system and make decisions before an agent implements, then inspect and refine the result [00:06:29]-[00:09:11].
- **Chats hide decisions that teams need to share**: He argues that implementation-oriented chats are isolated and ephemeral, while a durable document can expose the key technical decisions for discussion before code exists [00:10:01]-[00:12:52].
- **Separate action from state**: In his proposed model, the shared document holds project context and decisions while agents perform actions from that state. New agents can start from the same source, and people can rebuild their own context by rereading it [00:12:52]-[00:14:30].
- **Move review before implementation**: Exploring several plans and deliberately not building some of them turns code velocity into idea velocity. Early agreement on the decisions that matter can reduce later code-review ambiguity and prevent parallel work from diverging [00:14:30]-[00:17:10].
- **Keep a durable decision log, then share it**: Dailey closes with three practices: distinguish planning from polishing, treat the plan as a view into the software system, and get a teammate's feedback before giving the plan to an agent [00:17:10]-[00:19:40].
