Marlene Mhangami presents a behavior-first testing loop for agent-generated web changes. She proposes turning each feature request into a failing Playwright browser test before implementation, letting the agent write code until that test passes, and spending most human attention on refactoring the result.

### Key Points Covered

- **More generated code does not establish more productive delivery**: Mhangami uses GitHub activity figures and a cited developer study to motivate the talk. Citing the study, she argues that AI amplifies gains in clean codebases and amplifies entropy (lower code quality and more rework) where its use goes unchecked. To keep a codebase clean, she points to test coverage, type coverage, documentation, and modularity. The talk does not present the study methodology or independently validate the extrapolated commit figures [00:15–04:12](https://www.youtube.com/watch?v=FWEInOtngmM&t=15s).
- **Behavior should survive internal refactoring**: Tests coupled to method names and other implementation details can fail even when user-visible behavior remains correct. Mhangami recommends targeting stable contracts and final outcomes instead [06:07–08:09](https://www.youtube.com/watch?v=FWEInOtngmM&t=367s).
- **Tests can copy the implementation's mistakes**: If an agent derives expected results from the code it just wrote, its tests may confirm what that code does rather than what the feature should do. A green suite and high coverage can therefore coexist with incorrect application behavior [07:12–08:09](https://www.youtube.com/watch?v=FWEInOtngmM&t=432s).
- **A feature request, not a new method, should trigger the first test**: Red-green-refactor means writing a failing test (red), making it pass (green), then cleaning up the code. With unit tests, adding a method to a class typically prompted a new test. In Mhangami's version, the expected behavior of a requested feature becomes a failing Playwright test before implementation [09:12–10:04](https://www.youtube.com/watch?v=FWEInOtngmM&t=552s), [11:44–13:51](https://www.youtube.com/watch?v=FWEInOtngmM&t=704s).
- **Playwright lets agents check behavior in a real browser**: Playwright is Microsoft's open-source end-to-end testing framework. It simulates user interactions in a visible (headed) or background (headless) browser. Mhangami names three ways to connect a coding agent to it: the Playwright MCP server, the Playwright CLI, and Playwright agents, which install planner, generator, and healer instruction files that plan, write, and fix tests [08:09–10:54](https://www.youtube.com/watch?v=FWEInOtngmM&t=489s).
- **The demo checks search and filtering through a browser**: Mhangami asks GitHub Copilot CLI to inspect a Tailspin Toys codebase and write failing feature tests before implementation. She then switches to a prepared session showing the implemented feature and browser interactions for text search, category filters, and price filters. The recording illustrates the workflow rather than showing every generation step live or comparing defect detection with other testing approaches [11:44–15:52](https://www.youtube.com/watch?v=FWEInOtngmM&t=704s).
- **Refactoring becomes the main human job**: Mhangami expects agents to make the red and green phases fast. Developers should then spend most of their time inspecting and improving the code the agent generated [09:12–10:04](https://www.youtube.com/watch?v=FWEInOtngmM&t=552s), [15:52–16:56](https://www.youtube.com/watch?v=FWEInOtngmM&t=952s).
- **Make the execution evidence reviewable**: She recommends attaching Playwright screenshots to pull requests and using headless execution when appropriate. She also recommends committing before asking an agent to repair failures and keeping each test focused on one feature [15:52–16:56](https://www.youtube.com/watch?v=FWEInOtngmM&t=952s).
- **The demonstrated scope is browser functionality**: In the Q&A, Mhangami suggests direct API tests when Playwright is unnecessary. She recommends Playwright agents for state-heavy cases and confirms that the presented approach is browser-based [17:57–18:46](https://www.youtube.com/watch?v=FWEInOtngmM&t=1077s).
