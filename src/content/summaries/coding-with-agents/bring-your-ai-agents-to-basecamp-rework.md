REWORK host Kimberly Rhodes speaks with 37signals co-founder and CTO David Heinemeier Hansson about Basecamp's command-line interface for external agents. Hansson frames CLIs and skills as an accessibility layer that makes existing product capabilities faster and more direct for agents than visual browser control.

### Key Points Covered

- **Agents could use Basecamp in a browser, but too slowly**: In Hansson's test, agents could work through Basecamp's web interface by analyzing screenshots, but each step was slow. A command-line interface keeps them working in text, which he says is far faster for them [02:09–05:56](https://www.youtube.com/watch?v=oE1Y_6W4Mj8&t=129s).
- **The CLI turns an agent's plan into shared project work**: In his demo, a request to plan a product launch becomes to-dos, comments, messages, assignments, and schedule items inside a Basecamp project, not a block of text [05:56–07:37](https://www.youtube.com/watch?v=oE1Y_6W4Mj8&t=356s).
- **Hansson wants the coding-agent loop for project work**: Coding agents became useful to him once they could run code and tests and fix what failed. He wants the same loop for setting up projects, dividing work, and following up, with the results shared in Basecamp [08:25–09:28](https://www.youtube.com/watch?v=oE1Y_6W4Mj8&t=505s).
- **Make the product usable by agents before building AI into it**: Hansson recommends exposing a product through CLIs and skills rather than adding native AI features that do not yet improve the workflow [10:23–14:05](https://www.youtube.com/watch?v=oE1Y_6W4Mj8&t=623s).
- **Agents wrote most of the Basecamp CLI**: He reports that an agent wrote most of the CLI's code and says the same approach will extend to Fizzy and to the HEY email service [15:04–17:02](https://www.youtube.com/watch?v=oE1Y_6W4Mj8&t=904s).
