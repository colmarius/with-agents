In this Syntax video, a presenter who is not named in the title or captions explains why they rebuilt their personal agent system on Pi Durable, a library from the team behind the Pi agent harness for agents that keep working after their process crashes. The video is a user's walkthrough: it explains the problem from the perspective of someone building agents into apps, then demonstrates a Sentry-triggered pipeline that diagnoses a bug, fixes it, and opens a pull request.

For the library authors' own explanation of task recovery and retry limits, see [Understanding Pi Durable](/summaries/coding-with-agents/understanding-pi-durable) and [Pi Durable: Agents That Survive Crashes](/summaries/coding-with-agents/pi-durable-agents-that-survive-crashes).

### Key points

- **Unattended agents need to resume without repeating side effects.** In an interactive session, a person notices a stalled agent and tells it to keep going. The presenter argues that this breaks down when agents run for longer, take actions such as opening pull requests, and start from triggers such as automations, cron jobs, or webhooks. If a webhook-started agent crashes overnight, someone must discover what failed. A durable agent should resume at the step where it stopped and avoid repeating actions that must not happen twice, such as sending an email or opening a pull request [00:55–02:54](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=55s).
- **Custom agent apps repeat the same plumbing.** The presenter lists what they had to build for each agent app: a message table, a work queue, a socket that streams to the UI, steering when the user prompts mid-run, forking, pauses for approval, retry rules, summaries of old messages, and keeping application state in sync with what the agent did. They describe their earlier custom system as slow to build, brittle, and hard to debug, and say moving to Pi Durable let them delete about 8,000 lines of code [01:57–03:50](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=117s).
- **Pi Durable saves the run, not only the chat.** As the presenter describes it, the library writes what was said, each tool call, and what the agent is waiting on to storage as the run progresses. If the process dies, a new process opens the same storage and continues, and every connected client sees the same agent. Each tool declares whether it is safe to run again after a crash: repeating a search can fetch fresh results, while repeating an email send would duplicate it. Resuming a chat from its history is sometimes fine, especially for coding, but the durable record also covers tool calls the agent was about to make, pending approvals, and whether a deploy already happened [03:50–05:57](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=230s).
- **Every interface becomes a client of one shared run.** The presenter contrasts workflow engines, which usually follow controlled steps, with Pi Durable, where the agent chooses its next step and tool calls. This is the presenter's characterization, not a reliability comparison. Because state lives in storage, a phone, terminal, or browser can join the same run and steer it with the same history. Several people with access can work on one agent at once, and the presenter says steering, forking, subagents, and shared waits for approvals or timers become easier to build [05:57–08:04](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=357s).
- **It is a JavaScript library, not a Cloudflare-only service.** The presenter says Armin's version runs entirely in the browser with IndexedDB storage, while their own runs on a Mac mini with Node.js and SQLite. It can also run inside a Durable Object or on celld, the Deno team's self-hosted Durable Objects runtime [12:48–13:45](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=768s), and connect to any model provider, including local models [07:00–09:01](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=420s). The opening lists other deployments, including a browser-only agent, an agent on an Android phone, and one on a photo frame [00:00–00:55](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=0s).
- **The demo turns a production error into a pull request.** A bug in the presenter's app reaches Sentry, which sends a webhook through a Cloudflare tunnel. The system first decides whether the error is a bug it should fix or something it cannot fix, such as a synthetic worker failure. It then gets a root-cause analysis from Sentry's Seer agent: the cart total read a discount percentage on every item, but full-price items had no discount. The presenter stops the run after the analysis and resumes it, and the agent continues from that point to fix the bug, test it, and open a pull request. After the presenter merges the pull request, they say the system marks the issue resolved in Sentry and in their own system, leaving a record of what happened. They can later message the same agent run, with its full record, instead of briefing a new agent [08:04–11:06](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=484s).
- **Automatic merging is limited, and the safeguards are not shown.** The presenter says automatic merging is enabled for software they care less about: private tools for themselves or their family, not public, user-facing software. They say the demo skips several protections, including checks that the work is real, that the issue belongs to tracked software, and that one Sentry issue produces only one pull request when it recurs. Their claim that the system is far less buggy than their custom version is personal experience [11:06–12:48](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=666s).
- **The presenter places Pi Durable within a broader move toward durable agents.** They say OpenCode 2 can run as a library on a server or inside a Durable Object, Cloudflare's agent SDK already has a harness that runs Pi Durable in a Durable Object, and Pi creator Mario built a multiplayer agent app on Pi Durable that runs on an Android phone, with only model calls leaving the device [12:48–14:48](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=768s).
- **The examples folder is the suggested starting point.** For adding Pi Durable to an existing system, the presenter prefers the repository's examples folder to the README, which covers reload and restart, tool overrides, compaction, and child tasks. They pointed an agent at those examples as verifiable reference code and report good results [13:45–14:48](https://www.youtube.com/watch?v=BLRReTwV8Fc&t=825s).
