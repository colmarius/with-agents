Codex separates its agent from the interface people use to control it. Tibo Sottiaux explains why that boundary matters as OpenAI brings the agent into more products, and how the team decides whether to improve the model or the harness—the instructions, tools, and execution controls around it.

### Main takeaways

- **Rust helped enforce an agent–interface boundary, not just improve speed.** [18:44–21:55](https://www.youtube.com/watch?v=sLSTM9znQNs&t=1124s): Sottiaux describes correctness, efficiency, compile-time checks, and the team's Rust expertise as reasons for the choice. A separate Rust core also discouraged coupling the agent to one product interface, leaving it usable in other products. He says TypeScript or Python could have worked too; this is a design trade-off, not a claim that agents require Rust.
- **Open source improves feedback but creates real operating costs.** [21:55–26:07](https://www.youtube.com/watch?v=sLSTM9znQNs&t=1315s): the team wanted contributors to use Codex to improve Codex and to learn directly from the changing open-source ecosystem. Sottiaux reports easier onboarding and useful contributions, alongside low-quality submissions, awkward boundaries with internal repositories, and competitors shipping copied features before OpenAI releases them.
- **Model choice need not require changing the whole setup.** [26:07–28:56](https://www.youtube.com/watch?v=sLSTM9znQNs&t=1567s): supporting other providers' models avoids forcing users into a fork or a new setup just to try a model, while giving the team feedback from comparisons in the same harness.
- **Local execution and cloud execution solve different constraints.** [32:28–36:18](https://www.youtube.com/watch?v=sLSTM9znQNs&t=1948s): Sottiaux describes local tool execution as sandboxed by default, with permission requests for commands needing access beyond it; the cloud option runs tools in a managed VM instead. Local work preserves an existing development setup, while cloud machines avoid laptop resource and availability limits. He proposes—rather than demonstrates—using agents to recreate and maintain that setup in the cloud.
- **Better models can need fewer behavioral reminders.** [37:06–41:18](https://www.youtube.com/watch?v=sLSTM9znQNs&t=2226s): the harness supplies the instructions, tools, and execution controls around the model. Sottiaux's example is an instruction to run tests: a later model better infers that requirement without the reminder. Research and engineering decide together whether to change the harness or wait for a training improvement, depending on its expected arrival.
- **Agents need organizational context to answer organizational questions.** [41:18–43:26](https://www.youtube.com/watch?v=sLSTM9znQNs&t=2478s): new starters are encouraged to ask Codex about project state, ownership, and past decisions. Sottiaux connects this usefulness to access to code, Slack, and documents, supported by work in broadly accessible internal channels. This is the connected internal workflow he describes, not a capability available without the relevant data and permissions.
- **Review dependency assumptions, not just the changed code.** [47:38–49:43](https://www.youtube.com/watch?v=sLSTM9znQNs&t=2858s): Sottiaux describes models following dependency chains to find cases where a library behaves differently from its documentation, breaking an assumption in the calling code. He says automated security findings block OpenAI pull requests.
- **Passing checks does not settle whether a change is worth building.** [49:43–52:50](https://www.youtube.com/watch?v=sLSTM9znQNs&t=2983s): he argues for discussing a change's intent separately from code correctness. He also proposes agreeing on a component's behavior and invariants—conditions that must remain true, including resource-use, data-access, and security constraints—so internal changes need less repeated discussion if those guarantees hold. He does not describe how to enforce them.
- **Cheaper changes make good boundaries more useful, not obsolete.** [52:50–55:57](https://www.youtube.com/watch?v=sLSTM9znQNs&t=3170s): Sottiaux expects dependency upgrades and other maintenance to become increasingly automated, with good changelogs and documentation helping models reason through changes. He also describes rearchitecture as faster. But stable abstractions still limit how far a change propagates, letting a team iterate inside one component without disrupting the rest.
- **Merging Codex into ChatGPT was an execution and scaling project.** [1:02:53–1:06:57](https://www.youtube.com/watch?v=sLSTM9znQNs&t=3773s): Sottiaux contrasts a locally executed agent with ChatGPT's managed cloud stack. The work included running the full harness with a cloud computer efficiently at a much larger user scale and reconciling plugin and library differences. He describes a unified product as the direction of travel, rather than claiming every capability was already identical across interfaces.
