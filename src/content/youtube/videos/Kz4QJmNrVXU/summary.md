Matt Dailey, CEO and founder of Ref, calls the gap between higher AI-assisted output and unchanged team impact “velocity sickness.” He argues that teams should move consequential review earlier, keep decisions with people, and use durable shared plans as the state from which agents act.

Editorial: This is a founder presenting both a workflow argument and the problem Ref addresses. The talk offers operating guidance, but it does not measure a 10x productivity gain or compare shared documents with other coordination approaches.

## Key Ideas

- Dailey describes excess pull requests, divergent work, abandoned agent sessions, and agent-made critical decisions as team-level costs of higher output [00:01:00]-[00:04:26].
- He uses output that exceeds its audience's capacity to argue that generated volume matters only when it creates impact [00:04:26]-[00:06:29].
- He says agent implementation shifts human engineering work toward collaborative planning before implementation and polish afterward [00:06:29]-[00:09:11].
- Dailey proposes durable documents rather than isolated chats for exposing technical decisions and aligning a team [00:10:01]-[00:12:52].
- In his model, the document holds shared state while replaceable agents perform actions from that context [00:12:52]-[00:14:43].
- Moving review before implementation shifts effort from code velocity toward exploring and selecting ideas [00:14:43]-[00:17:39].

## Practical Implications

- Distinguish planning from polishing, use the plan as a view into the relevant software context, and share it with a teammate before implementation [00:18:35]-[00:20:16].
- Preserve key decisions in a durable artifact so parallel agents and people can restart from the same context [00:16:48]-[00:18:35].
