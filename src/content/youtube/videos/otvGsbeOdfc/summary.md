REWORK host Kimberly Rhodes speaks with 37signals co-founders Jason Fried and David Heinemeier Hansson about finishing Basecamp 5. Their discussion uses the release's AI-accelerated design work to distinguish disposable exploration from durable production software.

## Key Ideas

- Hansson says agents let designers take prototypes much further, but the resulting backlog of working code still needs experienced review for scale, database load, and architectural fit. [00:03:50]-[00:05:57]
- He describes a workflow in which designers iterate freely with agents until they know what a feature should do, then programmers turn that working specification into production code rather than assuming the prototype should ship. [00:05:57]-[00:09:50]
- Fried argues that speed does not create durability: established products still require people to exercise edge cases, inspect interactions, and refine details before exposing changes to a large audience. [00:10:52]-[00:11:55]
- Hansson says cheaper implementation raises the value of taste, product direction, and cohesion because teams can now generate more plausible features than a product should contain. [00:12:42]-[00:13:38]
- Their agent-accessibility work reached a demonstration quickly, but Hansson says moving from roughly 75% to a polished result became proportionally harder because every fast-created surface still needed consistency and ergonomic review. [00:13:38]-[00:15:22]

## Practical Implications

- Use agents to shorten the feedback loop for product discovery, then establish a deliberate handoff into production engineering.
- Define “done” with durability, consistency, edge-case, and operational checks rather than functional demonstration alone.
- Preserve a stopping rule: abundant implementation capacity can increase feature bloat and finishing work.

## Questions and Tensions

- The 75%-to-100% framing is a practitioner estimate, not a measured delivery model.
- Rewriting a prototype may protect architecture but can also shift a large review and implementation burden onto senior programmers.
- The episode does not define objective criteria for deciding when generated code can be retained versus replaced.
