*All English wording below is an editorial translation/paraphrase of the Italian captions; nothing is a verbatim quotation.*

Salvatore Sanfilippo examines the fatigue created by coding agents that make more work possible without preserving the focused experience of traditional programming. He argues that burnout is not inevitable, but avoiding it requires limiting parallel work, staying close to the code, and deliberately preserving human participation in the implementation loop.

## Key Ideas

- Sanfilippo likens access to automatic programming to suddenly acquiring the ability to fly: the new capacity creates pressure to use it even without a necessary destination. He connects that pressure to an appetite for ever more output and to token fatigue. [00:00:01]-[00:01:04]
- Coding agents enable asynchronous and parallel work, including unattended overnight runs. That creates a new form of anxiety about whether an agent stopped, followed the wrong path, or is waiting for a small correction. [00:01:04]-[00:02:14]
- Traditional programming can produce a sustained flow state in which the developer understands the experiment and direction. Sanfilippo says that experience disappears in hands-off vibe coding, where the developer lacks a working model of the code. [00:02:14]-[00:03:10]
- Even a specification-led workflow can exclude the developer while the model works. Starting another project during each wait fragments attention and turns increased parallel capacity into severe cognitive stress. [00:04:03]
- Focused programming imposes acute fatigue that eventually makes a person stop. Supervising agents can instead extend the working day while accumulating less visible chronic fatigue, which Sanfilippo associates with burnout and reduced enjoyment. [00:05:04]-[00:06:16]
- He does not treat this outcome as inherent to the tools. For projects that require understanding, he recommends working on one project at a time, inspecting and modifying the code, and remaining ready to give the next informed instruction. [00:06:16]-[00:07:33]
- Narrow unattended tasks such as optimization or bug searches can still run separately, but the main workflow should alternate agent work with human review and intervention. He says even a small amount of carefully examined human-written code can materially change how the work feels. [00:08:33]-[00:09:48]

## Practical Implications

- Limit concurrent agent sessions by attention capacity, not by how many processes the machine can run.
- Use overnight autonomy for bounded work with inspectable results rather than as the default development mode.
- Stay in one repository while the agent works: read the diff, inspect adjacent code, and prepare the next evidence-based instruction.
- Track sustained working hours, context switches, and recovery—not only token use and completed tasks—when evaluating productivity.

## Questions and Tensions

- The account is based on Sanfilippo's experience rather than a measured comparison of workloads, error rates, or burnout outcomes.
- Some teams may need parallel agent work to meet cost or schedule constraints even when it worsens individual focus.
- Close code involvement can preserve understanding but may reduce some of the throughput that motivates agent adoption.
- The appropriate balance may differ between exploratory prototypes, routine maintenance, and safety-critical systems.
