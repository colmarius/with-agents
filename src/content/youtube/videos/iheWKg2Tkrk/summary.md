Eno Reyes of Factory presents "agent-native development" as an organizational shift from developers executing individual implementation steps toward orchestrating agents across planning, coding, review, and operations. ([source title](https://www.youtube.com/watch?v=iheWKg2Tkrk)) He argues that this depends less on unconstrained vibe coding than on centralized context, standardized process, reliable checks, organizational memory, parallel infrastructure, and enterprise controls. ## Key Ideas

- Reyes says delegating most software-lifecycle tasks requires task-management interfaces, context from engineering systems, consistently reliable output, and infrastructure for many parallel agents. [00:00:55]-[00:02:51]
- Reyes rejects vibe coding as sufficient for complex legacy systems and describes agents as tools that amplify rather than replace human engineering expertise. [00:02:51]-[00:03:56]
- Reyes demonstrates a Factory droid grounding itself in repository state and memories, proposing a plan, requesting clarification, writing code, running pre-commit and lint checks, and opening a pull request that passes CI. [00:03:56]-[00:04:50]
- Reyes says missing context is a frequent cause of agent failure and recommends connecting meeting notes, whiteboards, product goals, architecture documents, code history, and organizational memory rather than relying on model improvements alone. [00:04:50]-[00:07:40]
- Reyes describes using customer transcripts, architecture, meeting notes, and existing assumptions to build a PRD and dependency-aware roadmap, treating process documents as a knowledge base through which agents learn how a team reasons. [00:07:40]-[00:10:49]
- Reyes says agents can assemble logs, metrics, prior incidents, runbooks, and team discussions into incident analyses, then turn learned patterns into updated processes and shared operational memory. [00:10:49]-[00:12:46]
- Reyes says developers' leverage shifts toward orchestration and clear communication, while enterprise adoption requires explicit ownership, auditability, security controls, and responsibility for destructive actions. [00:13:43]-[00:15:49]

## Practical Implications

- Editorial: Treat meeting notes, decisions, runbooks, PRDs, and architecture documents as executable context that must be current, access-controlled, and traceable to its source.
- Editorial: Require agents to expose plans, ask clarifying questions, run repository checks, and preserve evidence before granting broader parallel or operational authority.
- Editorial: Define ownership, audit logs, credential boundaries, destructive-action controls, and incident escalation before introducing agents into enterprise systems.

## Questions and Tensions

- Reyes reports that Factory has examined thousands of droid sessions and that some teams have cut incident-response time in half. [00:04:50] [00:12:46]
- Editorial: The talk does not provide sampling methods, baselines, failure rates, or independent evidence needed to generalize those product-derived claims.
- Reyes proposes extensive organizational memory spanning user interactions, meetings, code, architecture, operations, and response patterns. [00:03:56]-[00:12:46]
- Editorial: Centralized context can improve continuity while increasing privacy, retention, stale-knowledge, permission, and cross-team leakage risks.
- Reyes says organizations should move from execution toward orchestration while warning that YOLO mode is unsuitable for enterprise use. [00:09:47] [00:14:45]-[00:15:49]
- Editorial: Orchestration itself remains engineering work; scaling agent count without bounded authority, evaluation, and review can magnify correlated mistakes.
