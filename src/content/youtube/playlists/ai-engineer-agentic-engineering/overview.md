## Current Thesis

- Aditya Khandelwal of Amazon AGI Lab argues that coding-agent adoption at team scale requires leadership ownership, a shared repository harness, continuous feedback, and attention to human confidence and review capacity. ([summary](../../videos/aeTb5BdmTTc/summary.md))
- Dominik Kundel of OpenAI describes the then-current open-source Codex harness, its app-server protocol, and its Responses API integration as a stack for context construction, tools, sandboxing, action review, transport, continuation, and compaction. ([summary](../../videos/shRR1e2HXMk/summary.md))
- Arjun Singh of Superconductor argues that agentic engineering should make sessions, context, and artifacts portable across collaborators and tools rather than isolate work on one developer's laptop. ([summary](../../videos/OL7kfezynJM/summary.md))
- Anirban Chatterjee of Sonar argues that increasing coding-agent autonomy requires guidance before generation and independent, repeatable verification during generation and in delivery gates. ([summary](../../videos/03l29gJXpCE/summary.md))
- Matt Dailey of Ref argues that durable shared plans can move consequential decisions and team review before agent implementation. ([summary](../../videos/Kz4QJmNrVXU/summary.md))
- Justin Smith of Resolve AI presents always-on background agents as a way to monitor production changes and perform recurring operational work with accumulated system context. ([summary](../../videos/vSx5IULvBns/summary.md))
- Idan Gazit of GitHub Next argues that agentic engineering should improve group coordination and safely automate work beyond code entry rather than merely multiply individual output. ([summary](../../videos/iQ5xldZ9StU/summary.md))
- Denys Linkov of Wisedocs argues that stronger models can reduce refactoring cost while scoped work, verification, organizational guardrails, and business context remain necessary for legacy modernization. ([summary](../../videos/7vn4WpqNpck/summary.md))
- Frank Coyle of UC Berkeley uses Anthropic's Claude Certified Architect exam scenarios to teach explicit loops, specialized agents, context isolation, deliberate compaction, and non-interactive CI behavior. ([summary](../../videos/Z-c11pV_uvU/summary.md))
- Saoud Rizwan of Cline argues that AI-generated contribution volume and software-supply-chain risk are weakening community-maintained open source while increasing the strategic importance of portable open-weight infrastructure. ([summary](../../videos/CoEIs6Xm8m8/summary.md))
- James Shi of Datacurve presents Datacurve's DeepSWE as an authored benchmark designed to reduce exposure to public solution history and implementation-specific grading. ([summary](../../videos/Yk87oUPVaxU/summary.md))
- Editorial: Across the 11 incorporated talks, agentic engineering is less a model feature than a set of control surfaces around models: shared context, harnesses, collaboration, verification, planning, production state, evaluation, and provider and ecosystem boundaries.

## Stable Ideas

- Aditya Khandelwal of Amazon AGI Lab recommends progressive context disclosure, shared guidance, automated feedback loops, and continuous maintenance of repository-specific agent infrastructure. ([summary](../../videos/aeTb5BdmTTc/summary.md))
- Editorial: Kundel's then-current Codex design illustrates reusable harness concerns—progressive tool loading, sandboxed actions, context-aware escalation review, and compaction—but its specific APIs and mechanisms are not stable contracts. ([summary](../../videos/shRR1e2HXMk/summary.md))
- Arjun Singh of Superconductor recommends cloud sandboxes with scoped credentials, shared work artifacts, model independence, and codebase-specific evaluation. ([summary](../../videos/OL7kfezynJM/summary.md))
- Anirban Chatterjee of Sonar proposes generation-independent, auditable verification and explicit quality gates that feed findings back to coding agents. ([summary](../../videos/03l29gJXpCE/summary.md))
- Matt Dailey of Ref recommends durable, team-visible decision records that supply shared state to replaceable agents. ([summary](../../videos/Kz4QJmNrVXU/summary.md))
- Editorial: Smith's Resolve AI examples suggest bounding recurring operational agents with explicit triggers, tools, context, expected reports, and escalation; the talk does not specify production-action approval boundaries. ([summary](../../videos/vSx5IULvBns/summary.md))
- Idan Gazit of GitHub Next recommends deterministic capability constraints, staged writes, audit logs, shared plans, and collaboration context for unattended or multiplayer agent work. ([summary](../../videos/iQ5xldZ9StU/summary.md))
- Denys Linkov of Wisedocs recommends validating end-to-end behavior and system understanding rather than accepting generated scaffolding as evidence that a large refactor is complete. ([summary](../../videos/7vn4WpqNpck/summary.md))
- Frank Coyle of UC Berkeley recommends explicit loop state, narrowly equipped subagents, bounded outputs, and separate permission policies for interactive and unattended execution. ([summary](../../videos/Z-c11pV_uvU/summary.md))
- Editorial: Rizwan's examples raise separate infrastructure questions about model/provider portability, dependency risk, and contribution policy; his cost comparison and open-weight case are anecdotal and vendor-interested. ([summary](../../videos/CoEIs6Xm8m8/summary.md))
- James Shi of Datacurve recommends inspecting task provenance, repository diversity, Git-history exposure, verifier isolation, and whether grading rewards behavior instead of a single implementation. ([summary](../../videos/Yk87oUPVaxU/summary.md))
- Editorial: Taken together, the talks treat surrounding system design as part of agent performance rather than attributing outcomes to the model alone.

## Emerging Ideas

- Aditya Khandelwal of Amazon AGI Lab describes one shared skill that handles the path from completed code to a review-ready pull request, backed by CI, automated review, issue tracking, and recurring code maintenance. ([summary](../../videos/aeTb5BdmTTc/summary.md))
- Dominik Kundel of OpenAI describes read-only subagent review of escalated actions and explicit goal-completion signals for continuation loops. ([summary](../../videos/shRR1e2HXMk/summary.md))
- Arjun Singh of Superconductor describes agents that turn signals from meetings and collaboration tools into inspectable prototypes or pull requests. ([summary](../../videos/OL7kfezynJM/summary.md))
- Anirban Chatterjee of Sonar says its proposed nested generation and delivery loops combine computational and LLM-based checks. ([summary](../../videos/03l29gJXpCE/summary.md))
- Matt Dailey of Ref proposes separating durable project state in documents from actions performed by replaceable agent sessions. ([summary](../../videos/Kz4QJmNrVXU/summary.md))
- Justin Smith of Resolve AI describes schedule-, event-, and message-triggered operational agents that reuse evolving production context. ([summary](../../videos/vSx5IULvBns/summary.md))
- Idan Gazit of GitHub Next describes natural-language background workflows compiled into constrained playbooks and shared documents used as collaborative agent control surfaces. ([summary](../../videos/iQ5xldZ9StU/summary.md))
- Denys Linkov of Wisedocs reports that newer models completed selected legacy refactoring tasks more effectively while still producing a fast zero-shot result that omitted core work. ([summary](../../videos/7vn4WpqNpck/summary.md))
- Frank Coyle of UC Berkeley presents withholding prior reasoning from specialist critics as intended to reduce inherited anchoring and convergence; the talk does not compare it with full-context review. ([summary](../../videos/Z-c11pV_uvU/summary.md))
- Saoud Rizwan of Cline predicts that open-weight models and competing inference hosts will make model and provider portability more important to coding-agent systems. ([summary](../../videos/CoEIs6Xm8m8/summary.md))
- James Shi of Datacurve reports that prompt wording can suppress self-testing and that accessible Git history can enable solution search; he identifies harness effects as future comparative work. ([summary](../../videos/Yk87oUPVaxU/summary.md))
- Editorial: The shared question is becoming less “which model?” and more “which context, workflow, verifier, permission, state, and feedback boundary produced this behavior?”

## Practical Implications

- Editorial: Treat repository guidance, tools, CI, review policy, and maintenance loops as one versioned agent environment with named ownership.
- Editorial: Measure adoption through review capacity, incidents, intervention, context use, and accepted outcomes rather than generated pull-request volume.
- Editorial: Make sessions and decision artifacts visible to collaborators while scoping sandbox credentials, networks, and production actions to the task.
- Editorial: Move independent verification into both agent loops and delivery gates, then evaluate the verifier rather than assuming another model is an independent authority.
- Editorial: Preserve consequential decisions as durable team state and distinguish planning, execution, and polish so agents do not silently own product direction.
- Editorial: Start background production agents on bounded recurring work with inspectable outputs and explicit escalation before expanding action authority.
- Editorial: Keep unattended workflows non-interactive and enforce permissions, network access, secrets, and allowed write paths outside model prompts.
- Editorial: Evaluate large migrations through staged research, implementation, and end-to-end verification tied to system and business outcomes.
- Editorial: Test model and provider portability on representative repository work before accepting either frontier rankings or lower inference prices as sufficient evidence.
- Editorial: Separate open-source contribution policy, dependency security, and open-weight model strategy; they have related incentives but different evidence and controls.
- Editorial: Evaluate coding-agent benchmarks as systems that include task provenance, repository state, prompts, harnesses, and verifiers.
- Editorial: Keep shared workflows editable by their users and record where current controls or evaluations do not represent production work.
